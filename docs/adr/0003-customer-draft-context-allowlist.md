# Customer Draft is built in a separate LLM call from an allowlisted context

The Customer Draft is generated by a second LLM call that never sees anything outside the allowlist. That way the model has no Internal Identifiers available to leak, rather than relying on it being told not to.

The draft context contains only:
- the customer-safe enums from the first call (`customer_status`, `impact_category`, `customer_action_needed`)
- each Cited Incident's Service and Severity
- each Cited Incident's `title`, `description` and `resolution_summary`, with no `id`

The engineer's question and any uncited Candidates are excluded.

## Consequences

- **Business rule:** `title`, `description` and `resolution_summary` are customer-visible, so they must be kept free of Internal Identifiers. The guarantee holds only while the data obeys this rule. Any future internal-only field must stay off the allowlist.
- As a backstop, the draft output is rejected if it contains a Candidate ID or matches a hostname, IP or email pattern. When it is rejected, a canned safe draft is returned instead.
- Assist makes two LLM calls per request, which costs extra latency and tokens.
